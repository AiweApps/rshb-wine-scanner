# API и локальные активы

## HTTP

| Маршрут | Результат |
|---|---|
| `GET /` | Веб-интерфейс |
| `GET /health/live` | HTTP-процесс жив, `{"live":true}` |
| `GET /health/ready` | `{"ready":true}` и 200 либо false и 503 |
| `GET /api/status` | Готовность модели, совпадение профиля, очередь, лимиты, числа карточек |
| `POST /api/recognize` | `{"view":…}` — цели и карточки для интерфейса |
| `POST /v1/eval/predict` | `{"slug":"…"}` либо `{"slug":null}` |
| `GET /api/reference/{slug}.jpg` | Локальная миниатюра эталона или 404 |

Оба POST принимают multipart-поле `image`. Необязательное `target_roi` — JSON-массив
`[x1,y1,x2,y2]` в пикселях оригинала **после применения EXIF-ориентации**.
Рамка должна иметь положительную площадь и полностью находиться в изображении.

`view.bottles[]` содержит `instance_id`, `geometry`, `label_bbox`, `select_roi`,
`selectable`, `primary`, `addressed`, `decision`, `best`, `alternatives`.
`best` и `alternatives` — карточки с `slug`, `title`, `producer`, `category`,
`region`, `grapes`, `page_url`, `reference`. Доступность повторного распознавания
определяется `select_roi`/`selectable`; рамка показа не всегда пригодна для нового запроса.

`primary_instance_id` связывает главную цель с карточкой. При явной рамке оценочный
ответ берется у addressed-цели. Автоматическое равенство нескольких целей не
разрешается случайным выбором первой. Порядок кандидатов модели не меняется.
`probability` всегда null, `calibrated` false. `raw_slug`, `best_slug` — только
публичные строки старого общего ответа; полный внутренний `raw` не отдается.

Ошибки: `{"error":"code","message":"описание"}`; для временной занятости
добавлены `retry_after` и HTTP `Retry-After`. Не передаются исключения распознавателя
или пути его файлов. Лимит тела проверяется до разбора multipart; нужен Content-Length.

## Пакет веб-активов

```text
web-assets/
  manifest.json
  cards.json
  thumbnails/<sha256>.jpg
```

Манифест `wine-scanner-web-assets-v1` содержит профиль, происхождение экспорта,
числа карточек/эталонов и `files`: относительное имя → SHA-256 и размер.
`cards.json` формата `wine-scanner-cards-v1` содержит карточки по slug и
`reference_sha256`, если эталон доступен.

При запуске проверяются SHA самого манифеста из окружения, профиль и SHA каждого
указанного файла. Выход за каталог пакета запрещен. Файлы подключаются только для
чтения; изменение пакета требует нового манифеста и явной настройки.

Этот пакет **не содержит модельных весов** и не заменяет нативный runtime.
Ему отдельно нужны веса детекторов/B0/B3, индекс галереи, параметры ранжирования,
профили каталога и проверенная нативная OCR-среда. Текущий исследовательский runtime
дополнительно использует свои манифесты происхождения и проверки выпуска.

## Проверенная локальная редакция

27 сентября 2026: Docker Linux/arm64 → текущий Mac runtime. Внешний пакет содержит
2136 карточек и 2094 миниатюры, все ожидаемые эталоны экспортированы.
На двух ранее просмотренных фотографиях проверены карточки, рамки и оценочный
slug; для одной — явная ROI. Также выполнены запросы с невинным объектом и
неверным файлом. Браузер: две бутылки → выбор передней → эталон/ссылка.
Это приемка упаковки, не новый независимый тест модели.
