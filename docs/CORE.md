# Распознаватель в Docker на Linux

`wine_scanner_core` запускает модели и чтение текста PP-OCRv6 Medium на CPU.
Для работы нужны код из репозитория и отдельный пакет моделей и каталога.
Полные команды установки и настройки `.env` — в [README](../README.md#самостоятельный-запуск-в-docker-linux-pp-ocrv6).

## Состав

| Компонент | Содержимое |
|---|---|
| `recognizer/` | Исполняемый код распознавания: детекторы, визуальный поиск и выбор товара |
| `wine_scanner_core/` | Загрузка моделей, Linux-адаптер, проверки файлов и внутренний HTTP API |
| `docker/core.Dockerfile` | Образ с закреплёнными версиями зависимостей |
| Пакет `core/` | Веса моделей, эталоны, индекс и настройки |
| Пакет `web-core/` | Карточки товаров и миниатюры для интерфейса |

Пакеты находятся вне Git и подключаются только для чтения. `manifest.json`
перечисляет файлы с размерами и контрольными суммами SHA-256. Список исходников
и их контрольные суммы хранится в `recognizer/SOURCES.json`.

## Работа на Linux

Адаптер переключает вычисления моделей на CPU и подключает PP-OCRv6 Medium
вместо Apple Vision. Веса моделей сравнения изображений, поисковый индекс и
правила выбора товара сохраняются. OCR работает в два потока — это проверенная
конфигурация для Linux/ARM64.

Сервисы `core` и `gateway-linux` используют общее сетевое пространство.
Шлюз обращается к ядру по `127.0.0.1:8375`. На хосте интерфейс доступен по
`http://127.0.0.1:8387/`. Модели и OCR читают локальные файлы, HF/Paddle работают
в offline-режиме. Docker использует обычную bridge-сеть.

## Проверка установки

После настройки `.env`:

```bash
docker compose --profile linux build core gateway-linux
docker compose --profile linux run --rm --no-deps core verify
docker compose --profile linux up -d core gateway-linux
curl --fail http://127.0.0.1:8375/health/ready
curl --fail http://127.0.0.1:8387/health/ready
curl --fail -F 'image=@photo.jpg' http://127.0.0.1:8387/v1/eval/predict
```

Первый запуск включает проверку файлов и загрузку моделей и занимает несколько
минут. Для контейнера настроены 2 CPU и лимит 12 ГБ памяти; самому Docker нужно
выделить больше 12 ГБ, проверенный вариант — 16 ГБ.

Команды диагностики ядра:

| Команда | Что делает |
|---|---|
| `describe` | Показывает идентификатор сборки без загрузки моделей |
| `verify` | Дополнительно проверяет файлы кода и пакета по контрольным суммам |
| `preflight` | Проверяет согласованность профиля и результатов проверки происхождения данных |
| `serve` | Проверяет пакет, загружает модели и запускает HTTP API |

Команду передают после `core`, как `verify` в примере выше. `preflight` модели
не загружает; проверка может занимать несколько минут.

## Совместимость кода и данных

**Дескриптор ядра** — контрольная сумма его кода, пакета данных, OCR и параметров
исполнения. Команда `describe` вычисляет её без загрузки моделей.
`WINE_SCANNER_CORE_EXPECTED` закрепляет ожидаемое значение, а пакет карточек
привязывается к нему через `tools/bind_web_assets.py`.

Внутренний `/v1/core` описывает состав запущенного ядра. `/health/ready` и поле
`target_contract.profile_checksum` содержат идентификатор текущей конфигурации.
Исходный профиль сохраняется в `core_parent_profile_checksum` для сопоставления версий.

Результаты проверок обучающих данных фиксируются при сборке пакета в записи
`provenance`. Для работы сервиса обучающий корпус не нужен. При старте адаптер
принимает эти результаты только для предусмотренных вызовов, заново проверяя
файлы модели, галереи и активные правила совместимости. Реализация находится в
`wine_scanner_core/`; журнал исходников позволяет сопоставить её с распознавателем.

## Обозначения в исходниках

Исторические имена сохранены в коде и именах файлов для совместимости пакетов.
Они не являются режимами, которые нужно выбирать при запуске.

| Обозначение | Роль в текущем распознавателе |
|---|---|
| `B0` | Модель проверки «винный объект или нет». Не выбирает товар каталога |
| `B3` | Модель признаков этикетки для поиска похожих эталонов. Список кандидатов затем обрабатывается вместе с OCR |
| Ранжировщик | Компонент, который упорядочивает товары по признакам изображения и текста |
| Галерея | Эталонные фотографии, связанные с карточками товаров |
| Индекс | Заранее рассчитанные признаки эталонов для быстрого поиска |

## Что проверено

На Linux/ARM64 с 2 CPU и 12 ГБ проверены пять сценариев напрямую к ядру и через
шлюз: три вина, выбор рамкой и фото без вина. Все 10 HTTP-запросов прошли.
Веса и данные подключались отдельным пакетом, без рабочего каталога разработки.

Это проверка запуска и интеграции. Точность на больших наборах, время ответа
и область проверенных платформ приведены в [QUALITY](QUALITY.md).
