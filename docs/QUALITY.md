# Качество и границы

## Проверенный распознаватель

Версия профиля: `3c8c2da4fc718e1c65c98167f84805fa7c8941425d369f07f088f29e3b6f528a`.
Использует B3 для визуального поиска, B0 только для проверки винного объекта,
локальный OCR Apple Vision и ранжировщик. Обучение при упаковке не проводилось.

На последнем диагностическом прогоне: 521 фотография атласа и 96 контрольных
запросов, всего 617 запросов. 610 допустимых ответов и 7 ожидаемых отказов по
формату/входу. Число HTTP 200 не является числом верно распознанных вин.

| Срез | Результат |

| Правильная карточка среди первых пяти | 186/192 — 96,9% |

Это уже просмотренная диагностическая выборка, участвовавшая в разработке.
Результаты **не являются независимой оценкой** качества на новых фотографиях.
Все 521 фото проверены технически; правильный товар установлен не для всех.
В расширенном срезе остаются 13 ошибок. Неизвестная разметка не считается успехом.

Время полного прогона на Mac: медиана 2,42 с, p95 7,83 с, максимум 15,33 с.
Это время распознавателя в конкретных условиях, не гарантия задержки через
Docker, сеть или под нагрузкой. Скрипт организатора обрывает запрос после 10 с;
отдельные сложные кадры превышают этот предел.

## Известные ограничения

- Другая этикетка, закрытый текст, блики и похожие варианты сахара/сорта могут
  привести к неверной карточке. Обратная сторона бутылки не является целевым сценарием.
- Наличие нескольких бутылок требует отличать общую сцену от главной или выбранной
  цели. Оценочный endpoint выбирает карточку главной цели; это не новый ранжировщик.
- Отказ для неизвестного вина не откалиброван. Значения сходства не являются
  вероятностью правильного ответа; проценты уверенности пользователю не показываются.
- Для прямой загрузки поддерживаются JPEG, PNG, WebP. HEIC/MPO нужно предварительно
  преобразовать; исходники при этом следует сохранять.
- Карточка товара не гарантирует правильный год урожая. Ссылка и эталон берутся
  из каталога, а не придумываются по распознанному тексту.

## Почему распознаватель пока на Mac

Сохраненная проверка одного доступного PP-OCRv5 на 10 открытых фрагментах:
11/26 контрольных фраз против 18/26 у Apple Vision. Это проверка чтения фраз,
не точность распознавания вина. В нативном Linux/arm64 контейнере предыдущие
запуски завершались при создании распознавателя; успешный импорт библиотек
не подтверждает работу модели. Новый модельный прогон при упаковке не выполнялся.

Поэтому текущая схема — Docker для приложения, нативный Mac для моделей и OCR.
Полный Linux-инференс требует отдельной подтвержденной замены OCR.
