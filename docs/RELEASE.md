# Выпуск и демонстрация

## Что входит в выпуск

| Требование | Где проверить |
|---|---|
| Распознавание по фото средствами CV | Фото → модели → карточка конкретного товара каталога |
| Оценочный HTTP API | `POST /v1/eval/predict`, multipart `image`, ответ `{"slug":"…"}` |
| Веб-интерфейс | https://vines.aiweapps.com: рамки бутылок, выбор цели, карточка, эталон, ссылка |
| Мобильный клиент | https://github.com/AiweApps/rshb-hack-flutter, гостевой Bearer без cookies |
| Самостоятельный запуск | Docker Compose, профиль `linux`, с пакетом активов — [README](../README.md) |
| Архитектура | [ARCHITECTURE](../ARCHITECTURE.md): граница шлюза и распознавателя, владельцы данных |
| Воспроизводимость | Закреплённые версии пакетов и образов, SHA пакетов активов, журнал исходников, дескриптор ядра |
| Качество | Метрики с размером и происхождением выборки — [QUALITY](QUALITY.md) |

Клонирование репозитория не даёт веса, каталог и работающий распознаватель:
пакет активов поставляется отдельно.

## Сценарий демонстрации, до 7 минут

1. Фронтальное фото бутылки: рамка → карточка → эталон → ссылка на «Своё вино».
2. Сцена с несколькими бутылками: выбрать нужную, получить её карточку.
3. Неподдерживаемый файл и недоступный распознаватель: понятная ошибка вместо ответа.
4. Архитектура: какие модули за что отвечают, где модели и данные.
5. Измеренное качество и оставшиеся ограничения.

После распознавания пользователь получает ссылку на товар в каталоге.
Отдельного рекомендательного сервиса нет.

## Эксплуатация

Публичный сервис работает за HTTPS с гостевым входом, ограничением частоты и общей
очередью к модели; распознаватель — нативный процесс на Mac. Когда он недоступен,
страница открывается, а распознавание отвечает 503. Сервис не отдаёт диагностику
с локальными путями и не хранит загруженные фото как коллекцию.

Локальный запуск публикует порты только на 127.0.0.1. Для открытого доступа к
собственной установке нужны свой адрес, TLS, аутентификация и ограничение нагрузки.

## Перед публикацией новой версии

- Проверить всю историю Git и состав Docker-образов на секреты, личные данные и
  приватные адреса, а не только последний коммит.
- Убедиться, что веса, данные, фото и `.env` не попали в Git и образы.
- Пройти сценарий интерфейса на реальном фото и оценочный endpoint на запущенном
  сервисе; успешная сборка качество модели не подтверждает.
