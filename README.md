# Сканер винных этикеток

Фото бутылки → карточка вина, эталон и ссылка на «Своё вино».

## Статус

Локальная редакция для подготовки к сдаче. **Docker содержит API и веб-интерфейс.**
По умолчанию распознаёт существующий нативный сервис на Mac: компьютерное зрение,
B3, OCR Apple Vision и ранжировщик.

Дополнительно есть ядро для Linux CPU (`wine_scanner_core`, профиль Compose `linux`).
Это тот же распознаватель, но вместо Apple Vision в нём работает PP-OCRv6.
Его исполняемый код лежит в `recognizer/`, устройство описано в [docs/CORE.md](docs/CORE.md).
Для распознавания всё равно нужен отдельный пакет активов, клонирования репозитория недостаточно.

Веса, векторный индекс, каталог и фотографии не включены в Git или Docker-образ.
Для вариантаMac нужны нативный распознаватель и пакет карточек. Для Linux — отдельный пакет моделей, каталога и индексов.
Удаленный репозиторий и публичный адрес этой редакции пока не опубликованы.

## Возможности

- Загрузка JPEG/PNG/WebP до 20 МиБ и 24 Мп.
- Рамки найденных бутылок, выбор бутылки на полке или своей области изображения.
- Основная карточка и альтернативы, фото эталона, ссылка на каталог.
- Оценочный endpoint с одним `slug` от главной или явно выбранной цели.
- Проверка совместимости модели и каталога, ограниченная очередь, понятные ошибки.
- Распознавание локально; внешние OCR/LLM API не используются.

## Самостоятельное ядро в Docker (Linux, V6)

Код ядра включён. Пакет активов выдаётся отдельно и подключается readonly.
[Подготовка, команды запуска и результаты10HTTP-проверок](docs/CORE.md).
Проверено наLinux/ARM64 с2CPU; это функциональный smoke, не новаяоценкаточности.

## Шлюз к Mac в Docker

Нужны Docker Desktop с Compose и доступный на этом Mac распознаватель на порту 8175.
Он должен отдавать `/health/ready` и `/v1/recognize` с контрактом целей.
Нужен пакет `manifest.json`, `cards.json`, `thumbnails/` от того же профиля модели.

```bash
cp .env.example .env
```

В `.env` укажите три значения из квитанции экспорта:

```dotenv
WINE_SCANNER_ASSETS_HOST_DIR=/absolute/path/to/web-assets
WINE_SCANNER_ASSETS_SHA256=<sha256 файла manifest.json>
WINE_SCANNER_EXPECTED_PROFILE=<контрольная сумма профиля распознавателя>
```

Путь — на хосте, вне репозитория. Compose подключает его в `/assets` только для чтения.
Для Mac используется `http://host.docker.internal:8175`. `.env` игнорируется Git.

```bash
docker compose up -d --build
docker compose logs --tail 30
curl --fail http://127.0.0.1:8287/health/ready
```

При первом запуске проверяются все файлы пакета; дождитесь `{"ready":true}`.
Откройте [сканер](http://127.0.0.1:8287/). Существующий интерфейс на другом порту
не заменяется. Остановка этой редакции: `docker compose down`.

Порт хоста меняется через `WINE_SCANNER_PUBLISH_PORT`. Контейнер остается на 8287.
По умолчанию доступ открыт только с этого компьютера.

### Создание пакета каталога владельцем исходного проекта

Получателю готового пакета этот шаг не нужен. Экспортер требует исходное окружение
распознавателя; он проверяет каталог, эталоны и активный профиль до записи.

```bash
/path/to/recognizer/.venv/bin/python tools/export_web_assets.py \
  --source-root /path/to/recognizer \
  --out /absolute/path/to/new-web-assets \
  --expected-profile 'PROFILE_CHECKSUM'
```

Экспортер не изменяет распознаватель и отказывается перезаписывать существующий
пакет. Вывод содержит контрольные суммы и число карточек/изображений. После смены
профиля нужен соответствующий пакет и новые настройки; несовпадение блокирует запросы.

### Без Docker

Python 3.12+, те же внешние зависимости:

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
export WINE_SCANNER_ASSETS_DIR=/absolute/path/to/web-assets
export WINE_SCANNER_ASSETS_SHA256='MANIFEST_SHA256'
export WINE_SCANNER_EXPECTED_PROFILE='PROFILE_CHECKSUM'
.venv/bin/python -m wine_scanner
```

Здесь адрес распознавателя по умолчанию `http://127.0.0.1:8175`. Файл `.env`
автоматически читает только Compose; при запуске Python используйте переменные окружения.

## Проверка

```bash
curl --fail http://127.0.0.1:8287/health/live
curl --fail http://127.0.0.1:8287/health/ready
curl --fail -F 'image=@/absolute/path/to/photo.jpg' \
  http://127.0.0.1:8287/v1/eval/predict
```

Успешный ответ: `{"slug":"catalogue-slug"}`. Если подходящая главная цель не
выбрана: `{"slug":null}`. Это не уверенный отказ для всех неизвестных вин.
Оценочный скрипт организатора ограничивает запрос 10 секундами; сложные фото
могут не успеть. Полные измерения и границы — [качество](docs/QUALITY.md).

Для проверки интерфейса загрузите фото, выберите бутылку, убедитесь, что эталон
и ссылка соответствуют карточке. Сборка образа сама по себе качество модели не проверяет.

## Исходники

| Путь | Назначение |
|---|---|
| `wine_scanner/settings.py` | Настройки и допустимые адреса сервиса |
| `wine_scanner/contracts.py` | Ограничения входа, координаты и ошибки |
| `wine_scanner/application.py` | Очередь, готовность, представление результата и выбор slug |
| `wine_scanner/adapters/` | Клиент модели и проверенный локальный каталог |
| `wine_scanner/api.py`, `http.py` | Маршруты и сборка приложения |
| `wine_scanner/static/` | Интерфейс без отдельного frontend-сервера |
| `tools/export_web_assets.py` | Одноразовый экспорт каталога и миниатюр владельцем |
| `wine_scanner_core/` | Linux-ядро: проверка пакета активов, квитанция, CPU/PP-OCRv6 адаптер, API |
| `recognizer/` | Вендоренный serving-код распознавателя и журнал `SOURCES.json` |
| `docker/core.Dockerfile`, `docker/core-requirements.txt` | Образ ядра с точными версиями пакетов |
| `tools/bind_web_assets.py` | Привязка пакета карточек к дескриптору ядра |

## Ограничения эксплуатации

Очередь: один запрос к модели и до двух ожидающих. Недоступный сервис возвращает
503/502, таймаут — 504; неверный файл — 415/422, слишком большой — 413.
Веса автоматически не скачиваются, фотографии не добавляются в обучение.
Приложение не хранит коллекцию загрузок и не возвращает внутренний отчет модели.

HEIC/MPO предварительно преобразуйте в JPEG. Вероятность ответа не откалибрована.
Полный Linux-инференс проверен на пяти открытых сценариях черезядро иgateway.
Некоторые запросы дольше10с; нагрузка иx86_64 не проверены. Публикация репозитория остаётся отдельным шагом.
